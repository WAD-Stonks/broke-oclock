# Ingestion/admin API

The ingestion REST resources implement administrator-only dashboard, bounded run history, paginated draft review, one-page manual ingestion, OneMap address lookup and read-only user listing. Named Express handlers are assembled under `apps/api/src/rest/routers/ingestion`; parsing, runtime composition, authorization and persistence live in this module. The infrastructure probes remain `GET /api/health`, `GET /api/ready` and authenticated `GET /api/me`. Every write keeps the existing exact trusted-Origin policy and request-local cookie session checks.

## Disabled by default

Both `INGESTION_ENABLED=true` and `MONEYDIGEST_REUSE_APPROVED=true` are required before a provider request. These flags record operator approval; they do not establish a publisher licence. A run then bootstraps the fixed WORDPRESS source (`externalId=moneydigest.sg`, URL `https://www.moneydigest.sg/`) with `enabled=false`. A separately authorized database/operator decision must enable it. No arbitrary source selection or source-enabling endpoint exists. OneMap uses only server-side `ONEMAP_EMAIL` and `ONEMAP_EMAIL_PASSWORD`; partial/placeholder credentials disable lookup.

## Persistence and review

- Each run fetches page 1 with at most 20 posts. No scheduler, Telegram scraper or unbounded request loop is registered.
- Atomic source leases expire after 120 seconds. Releases compare the owner token. Request and post-write boundaries fence expired owners. Durable IngestionRun request-start timestamps enforce a 30-second cooldown across process restarts; failed requests also consume cooldown.
- Posts are identified by source and external ID, validated and hashed. Each parsed draft starts PENDING with NO_FIXED_LOCATION; no merchant matching, outlet association or coordinates are invented. Post-processing errors are isolated and stored as safe codes, never provider messages.
- DealSource snapshots contain the bounded JSON post (including title, body, excerpt and attribution) whose SHA-256 matches the pinned sourceContentHash. Reimport never rewrites a snapshot or an approved deal. Changed approved/rejected citations retain their deal and surface `SOURCE_CHANGED` on the post.
- Changed PENDING content creates a replacement PENDING revision with an incremented contentVersion. The old revision is marked REJECTED/superseded and its review metadata is invalidated; its immutable citation remains. `updatedCount` counts these draft replacements, not snapshot rewrites.
- Queue DTOs include `reviewReady`. Approval requires known, correctly ordered, nonexpired validity dates, unambiguous applicable offer amounts and matching current source evidence. Approval/rejection compares the exact pending contentVersion and CAS-writes each ImportedPost evidence row in the same transaction; ingestion's changed/failed-post upserts share that write fence even when Deal is left untouched. Concurrent/stale reviews return CONFLICT without rewriting approved deals or citations. Review notes are mandatory and bounded.
- Date-only validity uses explicit years and Singapore UTC+08:00 midnight, storing an exclusive UTC end. Unsupported dates, missing years, multiple validity statements and ambiguous prices remain unready.
- Parsing is **candidate-first, validation-second**: a small lossless lexer records original spans and treats adjoining letters, digits, underscores and Unicode combining marks as maximal identifier lexemes. It never recognizes a supported word/digit suffix within an identifier. Currency/percentage anchors create candidates even for missing or malformed operands; a separate complete `SGD`/`S$`/`$` marker inventory retains embedded markers (for example `xSGD6.50`) as invalid evidence even when a word lexeme swallowed them. Maximal numeric/punctuation runs are validated as a whole. Full title, body and excerpt are checked independently before display truncation; the validated post and immutable source snapshot are not rewritten.
- The numeric operand grammar is integer percentages (`1..100`, followed by `% off`/`% discount`) and integer/two-decimal SGD prices (`S$`/`SGD`/`$`, at most 1,000,000 minor units). Whitespace next to a marker is allowed, including decoded NBSP/HTML boundaries; whitespace inside a number, signs before/after currency markers, leading/trailing/repeated separators, unknown symbols, decimal percentages, unknown percentage operators and out-of-range values veto the entire offer. No rounding repairs precision. Word-form `percent`/`percentage`, including markers merged with quantities (`25percent`, `25percentage`, `percent25`), is inventoried independently as unsupported rather than disappearing beside a valid offer. Conflicting supported values retain an unready numeric draft; adding BOGO does not bypass validation.
- Ambiguous sentence/operand boundaries fail closed: `S$5.` is not repaired to `S$5`; integer prices remain supported with an explicit price word (for example `S$5 only`). A complete two-decimal price may close with one prose full stop before validity/end-of-field (`S$5.50. Valid ...`). A two-decimal price followed by whitespace and a percentage creates distinct spans; `S$5 50% off` is ambiguous and unready, not a rescued `50%` suffix.
- BOGO uses token-level phrase recognition (`buy one get one` with punctuation boundaries, and `1-for-1`/`one-for-one` with whitespace or single-dash separators) and a finite continuation grammar: optional `free`, optional `only`/`deal`/`special`/`promotion`, then end-of-field or one entirely consumed validity clause, with punctuation delimiters. Validity supports the existing explicit date-range/end-date forms; missing years remain unknown, not inferred. A validity **prefix** cannot hide later qualifications. Paid/discounted/unknown second-item conditions, the complete `2nd` ordinal lexeme, partial buy/get-one phrases, malformed merged buy/get quantities (`buy1`, `get1`, `buy_1`), and numeric expressions alongside BOGO are ignored across all title/body/excerpt evidence, before or after offer/validity. Ordinals and merged quantities are evidence only, never supported numeric operands; adding a supported duplicate cannot rescue them. Unknown non-second-item continuations retain an evidence-only PENDING draft with null validity dates and original raw validity text, never an approvable BOGO; this also preserves text-extraction/unknown-date regressions.
- Prefixed malformed buy/get quantities (`_buy1 _get1`, `xbuy1 and xget1`) are inventoried only in local paired offer context: both operators/quantities inside the same maximal identifier, or a buy-quantity identifier followed by a get-quantity identifier/complete `get one`, optionally joined by the complete word `and`. Contiguous prose-punctuation runs on either side of that connector have no delimiter-count limit (`_buy1 .... _get1` remains evidence); any other intervening word, identifier, numeric/currency token, non-prose symbol or field boundary ends this context. Underscores and combining marks may expose malformed evidence, never supported suffix fragments. Prefixed/interstitial ordinal-shaped identifiers (`_2nd`, `x2n_d`) likewise veto in local `item`/`items` context, within the same identifier or on either side through punctuation, not through intervening prose. Nearest grammar-bearing-token boundaries are cached in linear passes rather than repeatedly scanning growing punctuation runs. Full fields, including evidence beyond display limits, retain these vetoes; a supported duplicate cannot rescue them. Unrelated `Target1`, outlet/part identifiers and distant anchors neither create an offer nor restore the blanket mixed-identifier veto.
- Word-form percent-marker inventory also exposes underscores/combining marks inside maximal lexemes (`25per_cent`, `25peŕcent`, `per_cent25`, `per_centage`). A complete projected `percent`/`percentage` marker with a missing quantity is unsupported too. This projection creates veto evidence only; it neither normalizes the original post nor supplies a supported `%` operator or operand. Exact symbol-percent, SGD-price and BOGO controls keep their existing amounts and types, and named-product wording remains evidence-only.
- Named-product wording `buy one <product> and get another free` is retained only as an evidence-only PENDING draft. The bounded product span is one to eight complete word tokens, including HTML-separated words; malformed identifiers, numbers and punctuation do not supply product tokens. Product/continuation conditions are not inferred: validity dates stay null even alongside another supported BOGO cue, while original raw validity text and all malformed/qualified-evidence vetoes remain intact.
- Malformed numeric/operator evidence is a whole-source veto, not an omitted match: mixed-alphanumeric quantities consumed by currency, percentage or ratio candidates and exponent-like expressions (including `2e 50`, `2 e 50` and HTML-separated variants) remain unsupported. Percentage operators must be complete lexemes on both sides; `off2.50`, `xoff` and an attached numeric suffix such as `off.2.50` cannot become `off`. BOGO inventories retain ratio-shaped `for` combinations even when an operand is merged into the operator lexeme or the opposite operand is missing (`one-forone`, `1-forone`, `onefor-1`, `1-forx`); they are always invalid evidence, never supported offers. Embedded operands or externally delimited operand/operator context are required, so an unrelated word containing `for` is not itself an offer. A supported duplicate cannot erase this veto. Signed/decimal/exponent operands and sign/junk tails are not repaired to a `1`/`one` suffix. Both numeric and word ratios require whitespace or a single dash, with complete operand/operator boundaries; buy/get phrases retain their punctuation grammar. Ratio inventory caches separator-run boundaries in linear passes. Unrelated alphanumeric metadata such as `11am`, `4Fingers` and `B1-K05A` is not itself a numeric offer candidate; these same lexemes still veto an offer when consumed as malformed currency, percentage or ratio operands.
- Currency/percentage splitting checks the bounded initial two-decimal-price token prefix once, instead of repeatedly validating growing slices. A schema-bounded adversarial-input regression asserts an operation budget rather than a machine-dependent wall-clock deadline.
- The parser remains a deliberately narrow English food/offer grammar, not general NLP. Its conservative choices can ignore legitimate promotions, and it does not infer arbitrary unmarked numeric prose or multilingual/synonym-based conditions. Unknown HTML named entities remain visible text; numeric and common publisher entities are decoded. Output is text extraction, not a sanitizer suitable for `v-html`.
- Runs/accounts/queue are bounded to 50 items. Accounts expose only id/name/email/role/createdAt; no deletion, promotion or credential/session data is exposed.

## Offline tests

From `apps/api`:

```sh
pnpm exec vitest run --config vitest.config.ts tests/unit/ingestion-parser.test.ts tests/unit/ingestion-config.test.ts tests/unit/ingestion-runtime.test.ts tests/unit/ingestion-review-policy.test.ts
pnpm exec vitest run --config vitest.config.ts --no-file-parallelism tests/integration/ingestion.test.ts
```

Unit fixtures are synthetic. The integration suite uses real HTTP, Better Auth cookies and Prisma against a disposable MongoDB replica set; only external providers and the clock are injected with `createApp(config, { ingestion: runtime })`. Runtime production-composition coverage also exercises the real MoneyDigest transport with mocked fetch. No production DB, publisher fetch, real OneMap credential or deployment is needed.
